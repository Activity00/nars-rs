# ADR 0005：MCP stdio 工具接入

- 状态：已接受
- 日期：2026-11-09
- 实现：`crates/nars-tools/src/mcp.rs`

## 背景

内置工具覆盖了文件、搜索、Patch 和 Cargo，但外部能力（数据库、浏览器、项目专用脚本）需要标准协议接入。MCP（Model Context Protocol）是目前最通用的工具发现与调用协议。

阶段 7 的目标是：

- MCP 工具像内置工具一样被 NARS 调度；
- 外部工具拥有独立权限；
- 工具输出转换为结构化观察；
- 单个 MCP 工具失败不会阻塞 Session。

## 决策

实现两种 transport：

```text
narsd
  ├── StdioTransport  (JSON-RPC 2.0 over stdin/stdout → child process)
  └── HttpTransport   (Streamable HTTP POST → JSON or SSE response)
```

支持的方法：

| 方法 | 用途 |
|---|---|
| `initialize` | 协议握手、读取 serverInfo |
| `notifications/initialized` | 握手完成通知 |
| `tools/list` | 发现工具，支持 cursor 分页（最多 10 页） |
| `tools/call` | 执行工具 |

暂不支持：MCP prompts、resources、sampling、roots；HTTP 的 server-initiated GET stream 与断线续传（resumability）也未实现。这些不影响工具调用闭环。

## 工具转换

每个 MCP 工具转换为标准 `ToolManifest`：

```text
mcp_<server>_<tool>
```

名称中的非字母数字字符折叠为 `_`，并截断到安全长度。示例：

```text
server: "files server", tool: "read/path"
=> mcp_files_server_read_path
```

映射关系：

| MCP | ToolManifest |
|---|---|
| `name` | 本地命名空间化名称 |
| `description` | 描述 + server/tool 来源 |
| `inputSchema` | `input_schema`，缺失时使用宽松 object schema |
| — | `side_effect` 来自 server 配置，默认 `external_side_effect` |
| — | `requires_approval` 默认 `true` |
| — | `timeout_ms` 来自 server 配置，默认 60s |
| — | `tags = ["mcp", "mcp:<server>"]` |

## 权限

安全默认值：

- 所有 MCP 工具默认 `ExternalSideEffect`；
- 默认需要审批；
- `--approval deny` 会直接拒绝；
- `--approval auto` 只应在受信环境使用。

运维可以显式放宽某个 server：

```json
{
  "name": "local-fs",
  "command": "mcp-fs",
  "side_effect": "read_only",
  "requires_approval": false
}
```

即便如此，MCP server 自身仍然是独立进程，**不受 workspace sandbox 限制**。路径校验必须由 MCP server 自己完成，或只连接可信 server。

## 配置

### stdio server

```json
{
  "name": "files",
  "command": "npx",
  "args": ["-y", "@modelcontextprotocol/server-filesystem", "/tmp/project"]
}
```

### Streamable HTTP server

```json
{
  "name": "remote",
  "url": "https://example.com/mcp",
  "headers": {"authorization": "Bearer ..."},
  "timeout_ms": 60000,
  "requires_approval": true
}
```

`url` 存在时使用 HTTP，`command` 被忽略。`headers` 用于认证等静态头。

`narsd` 支持两种配置来源，可同时使用：

1. `--mcp-config <PATH>`：JSON 文件；
2. `NARS_AGENT_MCP_SERVERS`：JSON 字符串。

格式：

```json
{
  "servers": [
    {
      "name": "files",
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/tmp/project"],
      "env": {"LOG_LEVEL": "error"},
      "side_effect": "external_side_effect",
      "timeout_ms": 60000,
      "requires_approval": true
    }
  ]
}
```

也接受裸数组。启动时逐个连接：

- 成功：注册全部工具并记录数量；
- 失败：记录 warning，跳过该 server，`narsd` 继续启动。

## HTTP transport

- POST JSON-RPC，带 `Accept: application/json, text/event-stream`；
- 响应可以是单个 JSON，也可以是 SSE（逐 `data:` 块解析）；
- 保存 `initialize` 返回的 `Mcp-Session-Id`，后续请求自动携带；
- 发送 `MCP-Protocol-Version`；
- 通知类请求期望 `202 Accepted`；
- 请求超时由 `timeout_ms` 控制。

HTTP transport 不拥有子进程，生命周期由服务端管理；`StdioTransport` 仍会在 Drop 时
kill 子进程。

## 执行与观察

`McpTool::execute`：

1. 发送 `tools/call {name, arguments}`；
2. 解析 `content` 数组：
   - `text` → 拼接为 stdout；
   - `image` → 生成 `image` artifact（不保存 base64）；
   - `resource` → 生成 `resource` artifact（保存 URI）；
   - 未知类型 → 文本占位；
3. `isError=true` → `ToolResult::Failed`；
4. 写入 metadata：`mcp_server`、`mcp_tool`、可选 `structured`。

之后与内置工具完全一致：Broker 截断输出、Observation 转 NARS 事实、UI 显示卡片。

## 生命周期与并发

- 每个 server 对应一个子进程；
- 客户端使用 `Mutex` 串行化同一 server 的请求；
- 读取线程把 stdout 行送入 channel，`recv_timeout` 实现请求超时；
- stderr 独立线程记录 debug 日志，避免管道阻塞；
- `StdioTransport::drop` 关闭 stdin、kill 子进程并回收线程；
- `narsd` 退出时所有 MCP 子进程随之结束。
